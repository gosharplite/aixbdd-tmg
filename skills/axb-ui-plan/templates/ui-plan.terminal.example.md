# 終端 / TUI 與框架雛形規劃

## 介面範圍

- 目標系統介面：`tell-me-go -i 互動式 TUI 提示介面`
- medium：`terminal`
- 需求來源：`使用者故事 1 至 3、FR-004、FR-007 與 NFR-002`
- 上游依據：`spec.md、features/acceptance/互動提示.feature`
- 產出順序：`先定稿 ui/ui-plan.md，再依這份 plan 產出 ui/screens/*.txt 框架。`

## 終端視覺方向

- 風格來源：`沿用既有 CLI 版面語彙；若需求未自帶視覺規範，先透過 clarify 收斂面板層級與顏色可及性。`
- 本次風格結論：`高資訊密度但可掃讀的單一終端畫面：上方即時建議清單，中段多行編輯器，下方狀態列與 keybinding 提示。`
- 視覺重點：`建議清單的選取游標、編輯器游標、聚焦面板的視覺區隔，以及不可用狀態的灰階提示。`
- 審美原則：`框架必須像終端真的渲染出來的畫面；不把 keybinding 對照表、狀態轉移清單或分析備註寫進框架檔。`

## 畫面與流程

### 1. `啟動 / 編輯框架`

- 對應框架檔案：`ui/screens/entry.txt`
- 主要目的：`讓使用者輸入問題，並在輸入同時瀏覽即時建議，作為整個互動流程的入口。`
- 進入條件：`使用者執行 tell-me-go -i 進入互動模式。`
- 主要操作 key：`輸入文字、↑/↓ 移動建議、Tab 接受建議、Enter 送出、? 說明、Ctrl+C 取消。`
- 成功轉移：`送出後進入執行框架，完成後回到本框架並顯示輸出摘要。`
- 失敗回饋：`空白輸入或無法解析時，在原框架顯示錯誤列，不清空已輸入內容。`

### 2. `即時建議框架`

- 對應框架檔案：`ui/screens/10-suggestion.txt`
- 主要目的：`在輸入時提供來自 history / FS / tools 的即時建議清單。`
- 進入條件：`使用者在編輯框架輸入至少一個字元。`
- 主要操作 key：`↑/↓ 移動選取、Tab 接受、Esc 關閉建議。`
- 成功轉移：`接受建議後回到編輯框架，並將建議文字插入游標處。`
- 失敗回饋：`無可建議項目時顯示「無建議」佔位列，不改變輸入內容。`

### 3. `執行狀態框架`

- 對應框架檔案：`ui/screens/20-running.txt`
- 主要目的：`顯示指令執行中的步驟與最近輸出，讓使用者掌握進度。`
- 進入條件：`使用者於編輯框架送出可執行輸入。`
- 主要操作 key：`Esc 中止執行、? 說明。`
- 成功轉移：`執行完成後回到編輯框架並顯示輸出摘要。`
- 失敗回饋：`執行失敗時顯示錯誤摘要與建議下一步，回到編輯框架。`

## Keybinding 對照表

| Key | 作用 | 目標框架 | 預期結果 |
| --- | --- | --- | --- |
| `Enter` | 送出目前輸入 | `entry` | 歷史新增一筆、建議清單重算 |
| `Tab` | 接受目前建議 | `entry` | 編輯器插入建議文字、游標停在句尾 |
| `↑` / `↓` | 移動建議選取 | `entry` | 建議清單選取游標移動 |
| `Esc` | 中止執行 | `entry` | 顯示中止摘要 |
| `?` | 顯示快捷鍵說明 | `30-help` | 開啟覆蓋式說明框架 |
| `Ctrl+C` | 取消目前輸入 | `entry` | 清空編輯器並回到啟動框架 |

## 狀態轉移清單

1. `entry` --輸入文字--> `suggestion`（清單依 history / FS / tools 重算）
2. `suggestion` --`Tab` 接受--> `entry`（編輯器插入建議文字）
3. `entry` --`Enter` 送出--> `running`（顯示執行中狀態）
4. `running` --完成--> `entry`（輸出摘要後回到編輯）
5. `entry` --`?`--> `help` --`Esc`--> `entry`
6. 任何框架 --輸入無效--> 原位顯示錯誤列（不轉移）

## 互動與假資料原則

- 假資料策略：`以假歷史、假檔案路徑與假工具輸出，讓 reviewer 直接感受建議引擎與狀態列。`
- 互動原則：`每個框架都對回可操作 key；以假資料渲染清單、編輯器與狀態列的狀態切換。`
- 內容原則：`框架只放終端真的會渲染的內容；keybinding 對照表與狀態轉移清單留在本 plan。`

## 狀態與資訊揭露

- 使用者可見資訊：`輸入內容、建議清單、聚焦面板、執行狀態列與錯誤訊息。`
- 必須隱藏資訊：`內部工具參數、完整檔案系統索引，以及任何不應外露的伺服器內部資訊。`
- 主要 UI 狀態：`啟動、編輯中、建議可見、執行中、完成摘要、錯誤提示。`
- 角色或權限差異：`單一使用者；無多角色差異。`

## 驗證與錯誤回饋

- 輸入驗證：`送出前檢查非空；空白輸入在原框架顯示錯誤列。`
- 狀態衝突處理：`執行中仍顯示已送出內容，但不接受新的送出，直到回到編輯狀態。`
- 使用者可理解錯誤訊息：`錯誤列說明原因與下一步，例如「輸入不可為空，請重新輸入」。`

## 雛形輸出規劃

- 入口框架：`ui/screens/entry.txt`
- 預計輸出檔案：`ui/screens/entry.txt`、`ui/screens/10-suggestion.txt`、`ui/screens/20-running.txt`、`ui/screens/30-help.txt`
- 框架轉移原則：`只有在終端真的會切換整體畫面時才更換框架；否則優先在同一框架內切換狀態區段。`
- Review 目標：`讓 reviewer 不看 Markdown 也能逐鍵追蹤 key → state → outcome。`

## 終端實作切分建議

- 面板 / 元件切分：`建議清單面板、多行編輯器面板、狀態列與說明面板。`
- 共用元件或區塊：`選取游標、狀態列、錯誤列與面板邊框。`
- 對後端契約的依賴：`建議引擎輸出入、歷史寫入與工具輸出摘要。`
- 驗收重點：`從啟動、輸入、接受建議到送出與完成摘要的流程必須連續且可理解，且不暴露內部工具與索引細節。`
